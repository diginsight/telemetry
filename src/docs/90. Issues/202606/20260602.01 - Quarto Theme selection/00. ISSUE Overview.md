## 📝 DESCRIPTION

The Diginsight Telemetry documentation site ships a **runtime theme switcher** embedded in the "About" navbar dropdown (implemented in [header-includes.html](../../../../header-includes.html)). It lets a visitor pick any of 25 Bootswatch themes, loaded on-demand from the jsDelivr CDN, and persists the choice in `localStorage`. This issue tracks three connected pieces of work on that switcher plus the publishing pipeline:

1. **Pristine theme application** — when a predefined Bootswatch theme is selected it must render in its *original* form (no Diginsight orange navbar, no yellow highlight overrides leaking in).
2. **Dropdown menu coloring** — after selecting a theme (e.g. `cerulean`) the dropdown menu turned **black**; it must stay **white for light themes** and **dark for dark themes**.
3. **CI publishing of theme previews** — the GitHub Pages workflow had to publish both the main site and the per-theme comparison previews, with a discoverable navbar/footer link, while keeping the generated `docs-themes/` folder out of version control.

### Error Message
N/A — no exception. Symptoms were purely visual:
```
- Selecting a Bootswatch theme still showed the Diginsight orange navbar and yellow text highlights.
- After selecting "cerulean" (a light theme) the About dropdown menu rendered black.
- User report: "mm after hard refresh still black menu on light theme".
```

### Impact
- Predefined themes could not be evaluated in their authentic appearance because Diginsight customizations bled through.
- The black dropdown menu on light themes was a visible, repeatable cosmetic defect that undermined the switcher.
- The published GitHub Pages site did not expose the side-by-side theme comparison previews.
- A generated `docs-themes/` folder (~473 MB, 3001 files) had been committed, bloating the repository.

## 🔬 ANALYSIS

### Root Cause Analysis

#### 1. Customizations bleeding into predefined themes
The Diginsight navbar color and highlight styling come from two places that are **not** the Bootswatch sheet:
- `theme-light.scss` / `theme-dark.scss` are compiled directly into Quarto's `link#quarto-bootstrap` bundle. They cannot simply be removed at runtime — doing so breaks the page layout.
- `styles.css` / `styles-callouts.css` are separate body-level `<link>` elements (yellow highlights, navbar bulb icon, list/H1 fixes).

So loading a Bootswatch sheet on top is not enough: the SCSS-baked navbar/banner rules and the custom CSS links keep overriding the theme.

#### 2. Black dropdown menu
Bootstrap 5.3 colors components via the `data-bs-theme` attribute. Quarto forces `data-bs-theme="dark"` on the navbar so the navbar links read white on the colored bar. The `.dropdown-menu` inside the navbar **inherits** this dark scope. Once a Bootswatch CDN sheet loads, the dark scope resolves the menu background to near-black — even for light themes.

#### 3. "Still black after hard refresh" (NOT a code bug)
After the menu fix was implemented and verified, the user still saw a black menu. Investigation (Playwright live DOM inspection) proved the code was correct on freshly-rendered pages. The real cause: **`quarto preview` does not re-render already-built pages when a shared `include-in-header` partial changes** — only on content/config edits. Only the pages I happened to navigate to had been rebuilt; the page the user was viewing served stale HTML.

## SOLUTION ANALYSIS

### Fix Overview
The switcher was reworked so that selecting a theme (a) loads/updates the Bootswatch CDN link, (b) disables the Diginsight custom CSS links, (c) overrides the SCSS-baked navbar/banner to the theme's palette, and (d) scopes each navbar dropdown menu to the theme's light/dark mode. Selecting **Reset** restores the Diginsight defaults. The publishing pipeline was extended to build and ship the per-theme previews, with the generated folder removed from version control.

### Code Changes

#### 1. Per-theme dropdown menu scoping ([header-includes.html](../../../../header-includes.html))
```javascript
function applyMenuTheme(mode) {
  document.querySelectorAll(".navbar .dropdown-menu").forEach(function (m) {
    if (mode) { m.setAttribute("data-bs-theme", mode); }
    else { m.removeAttribute("data-bs-theme"); }
  });
}
```
- `mode` is the selected theme's `m` value (`"light"` / `"dark"`); `null` on reset removes the attribute so Quarto's default applies.
- Nested `ds-submenu` elements inherit the parent menu's `data-bs-theme`.

#### 2. Disable Diginsight custom CSS for predefined themes
```javascript
var CUSTOM_CSS_RE = /(^|\/)(styles|styles-callouts)\.css([?#]|$)/;
function setDiginsightCustomizations(enabled) {
  var links = document.querySelectorAll("link[rel=stylesheet]");
  for (var i = 0; i < links.length; i++) {
    if (CUSTOM_CSS_RE.test(links[i].href)) {
      links[i].disabled = !enabled;
      links[i].media = enabled ? "all" : "not all";
    }
  }
}
```

#### 3. Override SCSS-baked navbar/banner to the theme palette
```javascript
var OVERRIDE_STYLE_ID = "diginsight-theme-overrides";
function setThemeOverrides(t) {
  // creates/removes <style id="diginsight-theme-overrides"> with
  //   .navbar { background-color: <t.p> !important; }
  //   .alert-primary { ...var(--bs-primary-*-subtle/emphasis)... }
}
```

#### 4. Re-apply after `<body>` is parsed (fixes stale early run)
```javascript
function whenReady() {
  applyTheme(read());      // body-level custom CSS links now exist
  if (injectMenu()) return;
  // ...MutationObserver fallback...
}
```

#### 5. CI publishing + discoverability + ignore
- [.github/workflows/quarto-publish.yml](../../../../.github/workflows/quarto-publish.yml) — new step after render:
  ```yaml
  - name: Build Bootswatch theme comparison previews
    shell: pwsh
    run: ./build-theme-previews.ps1 -OutRoot docs/themes
  ```
  (runner kept as `ubuntu-latest`; `pwsh` is preinstalled and the script is cross-platform)
- [_quarto.yml](../../../../_quarto.yml) — added a **"Themes"** navbar item and a footer link → `/themes/index.html`.
- `.gitignore` — added `docs-themes/`; untracked the folder with `git rm -r --cached docs-themes` (3001 files) and deleted it locally (~473 MB reclaimed).

### Solution Features

#### ✅ Pristine predefined themes
- Bootswatch sheet layered on top, Diginsight CSS disabled, SCSS navbar/banner overridden to theme palette.

#### ✅ Correct menu coloring
- `applyMenuTheme()` scopes each menu to its theme's mode; submenus inherit correctly.

#### ✅ Verified via live DOM inspection
- Playwright confirmed computed `backgroundColor` / `data-bs-theme` for cerulean, darkly, united, and reset.

### Migration Considerations
#### ⚠️ Important: `quarto preview` does not rebuild on `include-in-header` changes
After editing [header-includes.html](../../../../header-includes.html), run a full `quarto render` (not just preview) to propagate the change to all pages. The production GitHub Pages build uses `quarto render`, so it is unaffected by this preview quirk.

#### ⚠️ Local link resolution for `/themes/`
`docs/themes/` only exists after [build-theme-previews.ps1](../../../../build-theme-previews.ps1) runs. The "Themes" link resolves on the published site; to resolve it locally run `./build-theme-previews.ps1 -OutRoot docs/themes` before previewing.

## 🎓 LESSONS LEARNED

### What Went Wrong
1. **Stale preview misread as a code bug**: `quarto preview` does not rebuild pages on `include-in-header` changes, so the user saw old HTML after the fix was already correct.
2. **Generated output committed**: `docs-themes/` (473 MB, 3001 files) was tracked, bloating the repo.

### What Went Right
1. **Layered, non-destructive approach**: kept the SCSS bundle intact and overrode only what was needed rather than fighting Quarto's compiled CSS.
2. **Empirical verification**: Playwright DOM inspection proved correctness objectively and isolated the stale-render cause.

### Improvements for Future
1. **Document the preview quirk**: after editing `header-includes.html`, always run `quarto render` for a full rebuild.
2. **Ignore generated folders up front**: add build outputs to `.gitignore` before first commit.
3. **Theme-aware components**: when customizing Bootstrap 5.3 in Quarto, account for the navbar's forced `data-bs-theme="dark"` scope on nested components.
